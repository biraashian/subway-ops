# T-0004 — People schema: persons, assignments, effective-dated wages, identity log
#
# Four new tables, all created by migration 021_people.sql, all shaped by
# SPEC-PPL-001 §5. This is the largest schema change the system has taken and
# the diff below is the review surface for it.
#
#   ref_employees              the person — one record, many store assignments
#                              (codex 06). Deliberately carries NO natural-key
#                              UNIQUE: measured on real data, no field or
#                              combination of fields identifies a human here
#                              (B-0014 → B, PLAN §6).
#   ref_employee_assignments   one person's presence at one store. UNIQUE on
#                              (store_number, clerk_id) — the join key back to
#                              stg_timeclock, and what makes derivation
#                              idempotent (INV-002).
#   ref_employee_wages         effective-dated pay. PK (employee_id,
#                              effective_date) is what makes "never updated in
#                              place" a database property rather than a caller
#                              habit (AC-011). hourly_rate is NUMERIC(12,4)
#                              CHECK > 0 (AC-014, codex 02).
#   ops_employee_identity_log  append-only audit of merge and split (AC-007,
#                              AC-008). B-0014's accepted cost is ~149 manual
#                              merges, so this table records real human
#                              decisions about who is whom.
#
# NOT VISIBLE IN THE LINES BELOW, and worth a reviewer's attention precisely
# because the gate cannot show it: 021 also DROPs and re-creates
# `ref_users_role_check`, widening the admin-surface role vocabulary from
# ('owner','field_manager','readonly') to add 'store_manager', 'office' and
# 'crew' per SPEC §5. The snapshot compares tables and columns only, so a
# constraint change on an existing table produces no drift line at all. That is
# a coverage gap in the check rather than an absence of change — raised as a
# bench item, and called out here so this declaration does not read as though
# the migration touched nothing but new tables.
#
# No data is backfilled. All four tables are created empty; T-0006 runs the
# first derivation.
#
# This declaration retires when T-0004 merges and post-merge rotates the
# baseline (D-028 rule 3).
